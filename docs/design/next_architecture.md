## 1. 产品与架构边界

RoDAQ 是可长期在线的数据采集和存储系统。一个 DAQ 可以在零任务时在线，可以同时管理多项录制，并能在任务完成、暂停或失败后继续提供控制和观测。任务状态、录制覆盖、产物完整性与平台健康分别记录。

`next` 从空的 Git 根提交起步。旧代码、目录结构、依赖和开发计划只供查阅。新实现直接以 Task 为录制控制对象，承担旧模型中 Activation 和 DAQ 单任务编排涉及的录制责任。DAQ 拥有任务集合及共享资源治理。基线验证用于识别必须重新证明的性质，旧测试通过记录只适用于其对应版本和负载。

平台需要覆盖两类交付场景：

- **长期在线、按需录制。** 多任务独立配置、运行、暂停和恢复。输出有界，录制间隙可查询，任务与产物可在进程重启后对账。
- **单任务持续录制。** Writer 按受控边界分片，内存、FD、磁盘和索引增长可控。分片轮换、断电耐久和故障后的覆盖范围分别验收。架构要为其留出边界，首个真实链路以有限时长的任务验证设计。

## 2. 组件与所有权

| 组件 | 拥有的事实与职责 |
| --- | --- |
| DAQ | 系统配置和生命周期，持有 TaskManager，管理系统健康、任务总预算和共享服务的关闭顺序。状态可简化为 `Offline → Online → ShuttingDown → Offline`，健康单独反映可用性和降级 |
| TaskManager | 任务注册、查找、枚举与移除，分配或校验 TaskId，协调跨任务资源准入。提供短事务接口，任务的长操作在管理器锁外执行 |
| Task | 任务配置、状态、每次控制操作的结果及录制运行世代。原生执行 configure、start、pause、resume、stop。各 Task 的控制操作独立串行 |
| Task 的本次运行 | Canonical Scope、绑定、准入、Payload 所有权、Plugin 实例、Pipeline 和清理凭据。可作为 Task 的内部状态。需要迟返或保留时，其资源根可以独立于公开 Task 句柄安全存活 |
| Acquisition / Storage Plugin | Acquisition 提交带身份和时间信息的数据，Storage 维护 Writer、持久化结果和真实封口事实。通过受控 ABI 与 Core 交互 |
| Recording Service | 任务意图及操作结果持久化，跨进程 Writer 排他，历史产物索引、保留策略和外部访问。使用 DAQ/Task 接口，实时任务转换由 Task 裁决 |
| Process Supervisor | 观察进程退出、卡死和 FailStop，实施重启、退避和熔断。任务级隔离与进程级隔离分别定义 |

Core 控制链为 `DAQ → TaskManager → Task`。数据链为 `Acquisition → Task Admission → Storage Pipeline → Writer`。注册表、API、账本写入和文件保留扫描均在数据热路径之外。Task 编排一次录制，Canonical、Admission、Payload、Storage 各自维护自己的不变量。

## 3. Task 生命周期

TaskId 在任务生命周期内稳定。每次成功建立运行时分配新运行世代与独立 Scope。启动过程中已经取得的资源也要绑定到对应的启动尝试，允许失败后准确清理。跨进程事件关联包含进程世代或等效唯一身份，避免重启后的旧结果作用于新运行。Scope 与 Record 身份继续遵循 Canonical 合同。

| 操作 | 合法入口 | 成功事实 |
| --- | --- | --- |
| configure | Created、Configured | 校验并发布完整配置，进入 Configured。启动时锁定本次配置版本 |
| start | Configured | 原子取得所需资源，准备源和 Writer，打开准入后进入 Recording |
| pause | Recording | 关闭本次准入，排空并结算已接纳记录，封口产物，达到规定清理屏障后进入 Paused |
| resume | Paused | 保留 TaskId 和配置，重新申请资源，创建新运行世代、Scope 和 Artifact，成功后进入 Recording |
| stop | Configured、Recording、Paused | 终结任务。正在录制则排空并封口，已暂停则结算既有产物，未启动则完成空任务。停止结果与产物是否存在分别记录 |

`Starting`、`Pausing`、`Stopping` 表示操作在途。每个 Task 同时只有一项修改生命周期的操作。重复请求通过 OperationId 返回同一结果，冲突请求有明确结果。系统停机先关闭新入场，再以同一绝对停机预算协调在途操作和任务清理。

首轮采用**暂停时封口**。Pause 成功后释放可重新取得的运行资源，并记录覆盖间隙。封口失败、在途访问尚未静止或执行超时，发布失败或待恢复事实。Caller Timeout、真实操作结果和资源已回收分别记录。恢复只能在旧运行对所需资源的访问已停止，并重新通过准入后开始。成功 Stop 发布任务终态，迟返只能补充原世代的清理结果。

## 4. 多任务资源与故障边界

- **分级预算。** DAQ 设置任务数量、线程、内存、队列、FD 和设备预算。TaskManager 对并发 Start/Resume 原子预留。进程级 Claim 对重叠外部资源和保留根做最后校验，跨进程 Writer 排他由运行部署提供。同一预算的预留和释放各有唯一记账 Owner。
- **录制隔离。** 每个 Task 独立准入、排队和对账。共享同一物理磁盘时，容量和带宽分别计费，保留封口余量。Task 失败只关闭自身及确定受影响的共享资源。全局故障进入 DAQ 级处理。
- **数据源共享。** 首轮验证独立任务和独立录制链路。相同外部资源能否并行使用由能力与冲突规则决定。采集一次后向多任务分发属于单独的数据面合同，需要明确共享 Payload、每任务背压和退出移交。
- **迟返与保留。** Supervision 保存未能安全回收的执行根与 Claim，按真实 Receipt 释放。前台入场不执行其他任务的 Recovery。回收超时不能放开旧 Writer 或卸载仍可能被调用的 DSO。
- **部署级隔离。** 进程内插件造成进程退出时，同进程任务都会受影响。需要跨任务故障域隔离的部署应分进程运行并独立验证。诊断输出可以失败，FailStop 退出须独立于诊断通道进度。

## 5. 数据路径和产物语义

1. **Admission 有明确提交点。** 提交前完成资源预留。正常拒绝不消耗 Sequence。Gate 后失败保留已分配身份，并在同一 Gate 域提交失败事实和 Cutoff。已接纳记录最终必须能按成功、失败或未知对账。
2. **生命周期不隐式改变记录语义。** 同 Scope 同 Stream 的顺序由 Runtime 保证。Payload 可释放与记录持久化是独立事实。Callback、完成事件和回收凭据按运行世代路由。
3. **正常关闭、格式完整与耐久分别发布。** Backend 提供写入、持久化和封口证据，Service 记录任务结果和产物可用性。磁盘满、部分文件和未知区间以实际事实呈现。
4. **分片归 Storage 执行，Task 记录覆盖。** 持续录制的目标是同一运行 Scope 下可观察的分片提交边界。已接纳记录只归属一个分片。旧分片封口和新分片打开必须有资源上界，故障时报告缺口或安全终止。暂停与进程恢复引起的 Scope 切换记录为明确的独立覆盖区间。
5. **持久账本提供重启依据。** Service 在对外确认操作前持久化必要事实。重启先验证排他权和旧 Artifact，再按策略重新准入。旧产物可能是 Complete、Partial 或 Unknown。重启后的运行从新世代开始。

## 6. 简化约束与迁移策略

- **一个状态有一个写入 Owner。** DAQ 状态、Task 状态、清理进度、插件静止证明及 Artifact 结果各自发布。可观察阶段从权威事实派生。已有消费者或故障测试能说明需要时，才保留额外中间状态。
- **一个清理执行路径。** Pause、Stop、启动失败、运行失败和系统停机复用相同清理逻辑，通过操作意图和已经取得的资源决定需要执行的步骤。对非幂等插件动作，按真实 Receipt 结算，迟返沿原事务处理。
- **组件接口描述调用方需要的能力。** Task 的正常启动和停止可以在少量入口内追踪。管理器无需逐项操纵 Admission、Dispatch、Completion 或 Release Worker。共享 Logging 由 DAQ 管理，任务通过身份标记和预算隔离。
- **先继承验证事实。** Canonical Identity、Admission/Sequence、Payload Ownership、Storage Completion、Plugin ABI 及已有回放工件是参考基线。可以移植满足新边界的代码。现有 Activation Lifecycle Port、Adapter 和 DAQ 内部单运行编排用作行为参考，新的调用边界按任务所有权重新设计。
- **复用以可验证为条件。** 优先复用 ROS 2、MCAP、ABI 兼容性和领域测试。接口调整后重新运行对应测试。对每个独立执行域记录状态 Owner、资源上界和关闭责任。

## 7. 首轮实现顺序与退出标准

| 阶段 | 可运行交付 | 通过条件 |
| --- | --- | --- |
| A. 单任务真实链路 | DAQ 在线，创建配置 Task，ROS 2 → MCAP，Stop，产物读回和回放 | 已接纳记录可对账，正常路径可跟踪，写盘失败发布真实终态 |
| B. 两个并行任务 | TaskManager 入场，任务 A 暂停与恢复，任务 B 继续录制，最后系统停机 | A 的旧世代迟返不影响新世代，B 持续有进展，资源冲突和停机期限可验证 |
| C. 平台长期运行 | 持久账本、磁盘准入与保留、重启对账、进程监督、真实后端矩阵 | 共享磁盘压力和故障下可回收并可追溯，RSS、FD、线程和保留根数量受控 |
| D. 连续录制 | 分片 Writer、Task Manifest 和跨分片读回 | 轮换下无隐式丢失、重排或重复，断电耐久与覆盖间隙有独立证据 |

首轮性能和正确性以真实数据链路为牵引，复用 D-078 的可比较工作负载做回归。生产声明须另有目标磁盘、负载、平台、后端和长时运行证据。设计评审需要确认暂停封口语义、首版连续录制范围、共享采集源的需求，以及部署所需的进程故障域。
